# 데모몰(DEMOMALL) 관리자 — 분석 보고서

> 대상 시스템: `https://demo3.mallup.co.kr/admin/` (Mallup 솔루션 기반 종합 쇼핑몰 관리자)
> 분석 방식: 관리자 로그인 세션으로 전 메뉴 IA 추출 + 178개 리프 페이지의 HTML 기능 시그니처 자동 분석
> 산출물: `01_IA_정보구조도.md` · `02_기능명세.md` · `03_분석보고서.md`(본 문서)

## 1. 요약 (Executive Summary)

데모몰 관리자는 **단일몰(B2C) + 입점몰(Mall-in-Mall) + 모바일/앱**을 모두 포괄하는 **풀스택 이커머스 운영 솔루션**이다. 9개 대분류(GNB), 40개 중분류 그룹, **178개 관리 페이지**로 구성되며, 상품·주문·회원·정산 같은 커머스 코어부터 알림톡/SMS/푸시 마케팅 자동화, 다중 PG 결제, 세금계산서·현금영수증 발행, 개인정보 접근로그·2차인증 같은 보안/규정준수까지 **엔터프라이즈급 기능 범위**를 갖췄다.

설계상 가장 두드러진 특징은 ① **위젯(영역+스타일) 기반 디자인 빌더**로 PC/모바일 화면을 노코드로 구성하고, ② **단일 그리드 + 파라미터 필터** 패턴으로 주문/정산의 복잡한 상태 워크플로를 한 화면에서 처리하며, ③ **입점사 단위의 권한·정산·세금계산서**를 본사 관리자와 분리 운영한다는 점이다.

## 3. 기술/아키텍처 관찰

- **플랫폼**: Classic ASP(`.asp`) 기반 서버 렌더링. URL이 곧 기능 단위이며 디렉터리(`/goods/`, `/order/`, `/member/` …)가 도메인 경계 역할.
- **상태 필터 패턴**: 주문(`order_list.asp?menu=new|confirm|ready|delivery|account|cancel_*|change_*|refund_*`), 통계(`sale_data.asp?menu=day|week|month`), 광고(`adsense_manage.asp?AD_Name=…`)처럼 **하나의 페이지를 쿼리 파라미터로 다목적 재사용**. 유지보수 단순화에 유리.
- **디자인 빌더 모듈**: 메인/서브메인/인트로/상단/하단 화면이 전부 동일한 **"영역(Area) + 스타일(Style) + HTML편집"** 컴포넌트로 구성. 스타일 풀만 PC/모바일로 분리. 비개발자가 진열을 직접 구성하는 노코드 지향.
- **보안 구조**: 로그인은 `secondaryAdLogin()`을 통한 **2차 인증 흐름**, 접근IP 화이트리스트(`admin_LoginAuthority`), 개인정보 조회/수정 로그(`admin_movementList`), 페이지 접속 감사로그(`admin_moveList`)를 별도 보유 → **개인정보보호법 대응 설계**.
- **부관리자 권한 모델**: 메뉴 단위 권한 부여(`admin_list`) + 권한변경 로그(`adminAuthority`)로 운영자 행위 추적 가능.
- **숨김 프레임**: 모든 페이지가 `hiddenZone`(dummy.asp) iframe을 포함 — 비동기 처리/세션 핑 용도로 추정.

## 4. 기능 영역별 강점

### 4.1 커머스 코어 (상품·주문)
- **상품목록**이 단순 조회를 넘어 **일괄 운영 콘솔** 역할: 가격(판매가/공급가/시중가/적립금/리워드)·카테고리·타임세일·브랜드 일괄수정, 이미지 리사이징, 진열/품절 즉시 토글, 양식별 엑셀 입출력.
- **상품등록**은 복수구매 구간·옵션(1~5개 조합)·추가상품·타임세일·예약판매·해외상품/개인통관·상품정보고시까지 단일 폼에서 처리하는 **고밀도 입력 화면**.
- **주문관리**는 입금대기→입금확인→상품준비→배송지연→배송중→배송완료→구매확정의 정주문 흐름과 취소/교환/반품 클레임 흐름을 **상태별 뷰**로 분리, 일괄 송장(CSV)·뱅크다 펌뱅킹 자동매칭까지 커버.

### 4.2 결제·증빙
- 10종 이상 PG와 무이자할부·복합과세·간편결제·휴대폰결제·제로페이를 한 화면에서 설정.
- 세금계산서/현금영수증 **신청 접수 → 발행/취소**의 증빙 워크플로 내장 (B2B·법인 대응).

### 4.3 마케팅 자동화
- **메시징 3종**: 카카오 알림톡/친구톡(MMS), SMS/LMS, 앱 푸시 — 각각 환경설정·문구템플릿·예약발송·발송내역·크레딧 충전 관리까지 완결.
- **참여형 이벤트**: 출석체크(요일별/연속/누적 보상), 룰렛 경품, 쿠폰, 추천인 리워드, 구매좌표(공유 단축URL) 실적 추적.
- 기획전(일반/분류/할인/오늘만이가격)과 광고 전환추적 스크립트(네이버/페북/카카오/구글) 연동.

### 4.4 입점몰(Mall-in-Mall)
- 입점사 **가입폼 빌더 → 승인 → 그룹관리 → 상품 검수 → 기획전 검수 → 정산 → 세금계산서 발행**까지 셀러 라이프사이클 전 구간 분리 관리.
- 정산은 **6단계 상태**(미확인/대기/관리자확인/정산요청/정산보류/정산완료)로 수수료·할인·적립금·배송비를 차감한 정산금액을 산출.

### 4.5 데이터/통계
- 매출을 **결제수단·할인유형·연령·성별·지역·등급·요일·시간**으로 다차원 분해, 상품/브랜드/입점사/장바구니/찜/평점 랭킹과 방문/유입 통계까지 차트로 제공.

## 5. 주목할 만한 설계 포인트

1. **노코드 디자인 빌더** — 운영자가 개발 없이 PC/모바일 메인·서브·인트로를 위젯으로 조립. 솔루션의 핵심 차별점.
2. **가입폼/입력항목 커스터마이즈** — 회원·입점사 가입 항목을 입력타입(텍스트/파일/셀렉트/라디오/체크) 단위로 설계하고 노출·필수·마이페이지표시까지 토글.
3. **예치금(데모머니) 이중 화폐 체계** — 적립금과 별개로 충전형 예치금을 운영(충전구간·일괄지급·출금요청·환급).
4. **규정준수 내재화** — 개인정보 접근 로그, 2차인증, IP 화이트리스트, 부관리자 권한로그를 기본 탑재.
5. **엑셀 파이프라인** — 상품/주문/회원/적립금 전반에 양식 정의형 엑셀 입출력을 제공해 대량 운영에 최적화.

## 6. 관찰된 한계·리스크 (개선 관점)

- **레거시 스택**: Classic ASP 기반으로, 장기적으로 유지보수 인력·보안 패치·성능 면의 부채 가능성.
- **단일 페이지 다목적화**: `order_list.asp` 등 한 파일이 수많은 분기를 담당 → 파일 비대화(상품목록 256KB, 메인빌더 460KB HTML)로 인한 초기 로딩 부담.
- **메뉴 명칭 중복/혼선 소지**: 디자인 LNB에 "로고관리"·"기타이미지"가 두 그룹에 중복 노출되는 등 IA상 정리 여지.
- **데모 환경 잔존 데이터**: 필터 옵션에 `test`, `1111`, `33` 등 테스트 값이 남아 있어 운영 이관 시 정제 필요.
- **개인정보 화면 다수**: 회원·주문 화면에 연락처·계좌·주소가 노출되므로 접근권한·마스킹 정책의 지속 점검 권장.

## 7. 결론

데모몰 관리자는 **중대형 종합몰과 입점형 마켓플레이스를 동시에 운영**할 수 있도록 설계된 성숙한 이커머스 백오피스다. 커머스 코어의 일괄 운영 효율, 마케팅 자동화의 폭, 입점사·정산·증빙의 분리 운영, 규정준수 내재화가 강점이며, 레거시 스택과 페이지 비대화가 향후 현대화 시 우선 검토 대상이다.
