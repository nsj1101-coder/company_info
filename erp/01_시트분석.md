# 라린느 ERP 엑셀 — 전체 시트 분석

> 원본: `검토용_라린느_ERP_v45 (1).xlsx` · **24개 시트 / 수식셀 약 16만+ 개**
> 분석일: 2026-06-12

## 0. 한눈에 보는 구조

라린느는 **Cafe24 · 스마트스토어 · 자사몰** 3개 쇼핑몰 어드민에서 주문을 받는데, 이게 분산돼 통합 관리가 안 됨. 그래서 이 엑셀로 ERP를 대체 중. 동작 원리:

```
[3개 몰 어드민에서 주문 export]
        │ (수동 복붙)
        ▼
 카페_26 / 주문서_26  ← 원천 주문 (자동분류 컬럼 U~AB)
        │ (수식 연동)
        ▼
   주문관리  ← 정규화된 주문 원장 (분석의 중심)
        │
   ┌────┼─────────────┬──────────┬─────────┐
   ▼    ▼             ▼          ▼         ▼
 재고관리 생산관리   반품관리   고객분석   매출/손익/기간 분석
   ▲                            ▲
제품SKU(상품마스터)        고객관리(고객마스터)
```

**핵심 한계 (= 웹 전환의 이유)**
1. **3개 몰 주문을 수동 복붙** → 누락·중복·시차. (← API 자동수집으로 해결)
2. **수식 16만+ 개** (카페_26 2.9만, 주문관리 3.1만, 매출상세분석 1.7만…) → 재계산 느림, 한 줄 깨지면 연쇄 오류. (← DB + 백엔드 로직으로 해결)
3. **권한 없음** — 한 파일을 다 같이 봄. (← 부서별 권한으로 해결)
4. 행 한도(수식이 1000행 등 고정범위) — 데이터 늘면 누락.

## 2. 시트별 상세

### 🗂 마스터

#### 제품SKU (1,375행 · 수식 0 = 순수 입력)
- **상품 마스터.** 컬럼: 상품명 · **SKU** · 제품 · 컬러 · 사이즈 · 원가 · 소비자가 · **온라인가격 · B2B가격 · 대리점가격 · 도매가/판매가(USD·엔화)** · 안전재고
- **채널별·통화별 가격을 한 행에서 관리** (온라인/B2B/대리점/해외). → 웹에선 `상품` + `채널별가격` 테이블로 분리 권장.
- SKU 규칙: `브랜드+카테고리+팔길이-제품명+색상-사이즈` (예: `LJKL-BLOMBK-XS`).

#### 고객관리 (2,568행)
- **고객 마스터.** 고객코드(A##) · 고객명 · 고객유형(병원/기업/개인) · 판매채널 · 담당자 · 연락처 · 이메일 · 지역 · 비고
- **자동등록**: 카페_26/주문서_26의 결제자명 기준으로 신규 고객을 중복제외하고 자동 코드부여(A008…). → 수식 8,757개.
- 참조: → 카페_26, 주문서_26.

### 📥 원천 주문 (3개 몰 통합 입구)

#### 카페_26 (3,696행 · 30열 · 수식 29,549)
- **온라인 3몰(단독몰/통합몰 등) 주문 원본을 붙여넣는 시트.** A~T = 몰 export 원본(주문몰·출고여부·주문번호·주문일시·결제자·상품명·옵션·수량·금액·연락처 등).
- **U~AB = 자동분류 수식**: 📅주문월 · 🏷채널분류 · ⚙주문상태(접수/생산중/출고완료/반품) · 🔧생산 · 🪡자수 · ↩반품 · 👤고객코드(고객관리 매칭) · 💰결제금액.
- 참조: → 고객관리. **이 시트가 사실상 모든 흐름의 출발점.**

#### 주문서_26 (500행 · 28열 · 수식 3,992)
- **오프라인/B2B 주문서**(전화·방문·단체). 구조는 카페_26과 동일(U~AB 자동분류).
- 참조: → 고객관리.

### 📦 작업 분류 보조 (수식 0 — 몰 export 원본 그대로)
- **제작중 (760)** · **자수-미출고건 (773)** · **해외배송건 (5)** · **이번주 출고 예정 (889)**
- 카페24 export 형식 그대로 붙여 작업 상태별로 나눠 보는 용도. → 웹에선 **주문의 상태/태그 필터**로 흡수(별도 시트 불필요).

### 📒 주문 원장

#### 주문관리 (2,275행 · 14열 · 수식 31,726) ★분석의 중심
- **정규화된 주문 한 줄 = 한 라인아이템.** 주문번호 · 주문일자 · 고객코드 · 고객명 · 고객유형 · 판매채널 · SKU · 제품명 · 수량 · 단가 · 총금액 · 반품수량 · 순판매수량 · 주문상태
- 자동: 고객명/유형/채널 = VLOOKUP(고객관리), 제품명/단가 = VLOOKUP(제품SKU), 총금액 = 수량×단가, 반품수량 = SUMIFS(반품관리), 순판매 = 수량−반품, 상태 자동판정.
- 참조: → 고객관리, 제품SKU, 반품관리, 생산관리, 카페_26, 주문서_26 **(6개 시트 = 가장 많이 참조)**.
- **거의 모든 분석 시트가 이 시트를 읽음.** 웹에선 `orders` + `order_items` 핵심 테이블.

### ⚙ 운영

#### 재고관리 (1,012행 · 수식 7,083)
- 브랜드·아이템·시즌·제품명·칼라·사이즈·SKU·**초기재고·입고·출고·현재재고·안전재고·재고상태·부족수량·발주권장수량·킵(예약)**
- **현재재고 = 초기재고 + 입고 − 출고 + 반품** (SUMIFS로 주문관리·반품관리 집계). 사람이 직접 안 적음.
- 재고상태/부족수량/발주권장 자동. 참조: → 제품SKU, 주문관리, 반품관리.

#### 생산관리 (1,427행 · 수식 4,795)
- 생산번호(PRD-) · 주문담당 · 생산일 · SKU · 브랜드명·제품명·컬러·사이즈 · **주문수량·생산수량·불량수량·입고수량** · **대표님확인** · 입고예정일·입고일 · 생산담당 · **공장(본공장/외주)** · 리드타임 · **지연여부** · **연결주문번호**
- 자수·제작중 시트와 연동. 참조: → 제품SKU.

#### 발주관리 (51행 · 수식 185)
- 발주번호(PO-) · 발주일 · SKU · 제품명 · 발주수량 · **공급사** · **원부자재·임가공·완사입** · 입고예정일·입고확인
- **발주 필요 품목 자동감지**(재고관리의 부족수량 기반). 참조: → 제품SKU, 재고관리.

#### 반품관리 (300행 · 수식 1,507)
- 반품번호(RTN-) · 반품일 · 반품처 · 주문번호 · SKU · 제품명·컬러·사이즈 · 반품수량 · 반품사유
- 카페_26의 "반품완료/취소" 비고 기반 자동 집계 + **SKU별 반품률** 요약. 참조: → 제품SKU, 주문관리, 카페_26.

#### 출고리스트 (1,268행 · 수식 11,347)
- 카페_26/주문서_26 기준 **출고 현황 카운트**(전체/출고완료/생산중/자수대기/반품). 물류팀이 출고 표기.

## 3. 번호 체계 표준 (운영가이드 발췌 — 웹에서 그대로 계승)

| 구분 | 형식 | 예시 |
|------|------|------|
| 주문번호 | `ORD-YYYY-NNN` / Cafe24 주문번호 | ORD-2026-001 |
| 생산번호 | `PRD-YYYY-NNN` | PRD-2026-001 |
| 반품번호 | `RTN-YYYY-NNN` | RTN-2026-001 |
| 발주번호 | `PO-YYYY-NNN` | PO-2026-001 |
| 고객코드 | `A` + 2자리 | A01 |
| SKU | 브랜드+카테고리+팔길이-제품명+색상-사이즈 | LJKL-BLOMBK-XS |

**입력 흐름(그들 기준):** ①고객관리 → ②제품SKU → ③주문관리 → ④발주관리 → ⑤생산관리 → ⑥반품관리 → (재고/손익/고객/대시보드는 자동).

## 4. 시트 간 참조 그래프 (의존 방향)

```
ERP대시보드  → 제품SKU·주문관리·재고관리·고객관리·고객분석·카페_26·주문서_26
출고리스트   → 카페_26·주문서_26
카페_26      → 고객관리
주문서_26    → 고객관리
주문관리     → 고객관리·제품SKU·반품관리·생산관리·카페_26·주문서_26   ★허브
고객관리     → 카페_26·주문서_26
고객분석     → 주문관리·고객관리
재고관리     → 제품SKU·주문관리·반품관리
반품관리     → 제품SKU·주문관리·카페_26
발주관리     → 제품SKU·재고관리
생산관리     → 제품SKU
리스트       → 제품SKU
매출상세분석 → 주문관리
손익분석     → 주문관리·제품SKU
일별/월별분석 → 주문관리
분기/연간분석 → 매출상세분석
```

**의존도 중심:** `주문관리`(6개 참조·6개에서 피참조) → `제품SKU`/`고객관리`(마스터) → `카페_26`/`주문서_26`(원천). 웹 DB 설계 시 이 4개가 핵심 테이블.

## 5. 웹 ERP 전환 시 데이터 모델 매핑 (요약)

| 엑셀 시트 | → 웹 테이블/기능 |
|-----------|------------------|
| 제품SKU | `products` + `product_prices`(채널별) |
| 고객관리 | `customers` |
| 카페_26 / 주문서_26 | `raw_orders`(채널 API 자동수집) → 정규화 |
| 주문관리 | `orders` + `order_items` |
| 재고관리 | `inventory`(입출고 로그 합산 뷰) |
| 생산관리 | `production_orders` |
| 발주관리 | `purchase_orders` + `suppliers` |
| 반품관리 | `returns` |
| 제작중·자수·해외·출고예정 | orders의 **상태/태그**로 흡수 |
| 분석 시트 8종 | 백엔드 집계 + 대시보드(쿼리) |
